# Contributing to taskli

Thanks for helping out. Please open (or comment on) an issue before sending a
change so the work is tracked.

## Setup

Requires Python 3.12+ and [`uv`](https://docs.astral.sh/uv/).

```bash
git clone https://github.com/calvinmcelvain/taskli.git
cd taskli

uv sync                        # creates .venv with the dev dependency group
source .venv/bin/activate      # Git Bash on Windows: source .venv/Scripts/activate
```

To use your checkout as the global `tk` command:

```bash
uv tool install . --force      # or: pipx install . --force
```

## Checks

CI (Python 3.12) runs all of these; run them before pushing:

```bash
ruff check .
black --check --line-length 79 .
isort --check-only .
mypy src tests
pytest -q                      # CI also enforces 95% coverage
```

Drop `--check` / `--check-only` to auto-fix formatting.

> [!TIP]
> If rich-output tests fail oddly, make sure `FORCE_COLOR` isn't set in your
> shell: `env -u FORCE_COLOR pytest -q`.

## Layout

- `src/taskli/`: the package. Dependencies flow one way,
  `cli` → `logic` → `{render, storage}` → `models/` → `exceptions`; see
  [`CLAUDE.md`](CLAUDE.md) for the architecture notes.
- `tests/unit/` mirrors `src/taskli/`. Tests that touch storage use the
  `taskli_env` fixture, which points `TASKLI_PATH` at a temp directory, so
  they never read or write your real `~/.taskli`.
- `completions/` holds generated shell-completion scripts and is guarded by
  `tests/test_completions.py`; see [`completions/README.md`](completions/README.md).
- `docs/` holds the user documentation linked from the README.

Line length is 79 everywhere.

## README screenshots

The SVGs in `docs/assets/` are generated by running the real CLI against a
throwaway storage directory with a frozen date, so they are reproducible.
Regenerate them whenever rendered output changes:

```bash
env -u FORCE_COLOR python scripts/gen_readme_assets.py
```

Commit the updated SVGs alongside the change that altered the output.
